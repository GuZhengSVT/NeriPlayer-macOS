# M9 验收记录：发布工程化

日期：2026-10-01

## 已实现

| 任务 | 实现 | 自动验证 | 实机边界 |
|---|---|---|---|
| M9-T1 版本与 About | `AppInfo` 统一 macOS SemVer/build；About 窗口；动态生成 AppIcon；`neriplayer://` 注册写入 Info.plist | 全量构建与测试 | 需在打包 `.app` 手动确认菜单、图标、系统 URL 唤起 |
| M9-T2 打包 | `Tools/package.sh` 生成 `.app/.dmg`，复制可发现的 Homebrew dylib，改写 `@rpath`；无证书时 ad-hoc | shell 静态检查与构建 | Developer ID、公证、干净虚拟机安装仍需真实证书/机器 |
| M9-T3 诊断 | About/帮助菜单打开诊断页；显示并导出版本、系统、架构和最后一条崩溃记录 | CrashReporter 单元测试与全量测试 | native signal/Swift trap 仍不由本地 NSException 捕获 |
| M9-T4 Sparkle | 明确暂缓，保留 GitHub draft release 通道 | 文档检查 | 需要 AppCast 服务器和更新签名策略后再接入 |
| M9-T5 CI 发布 | `v*.*.*` tag 触发 macOS build、DMG artifact、draft release；证书 secrets 可选 | YAML/actionlint（环境可用时） | GitHub runner、Developer ID secrets 和 notarization 服务需手动验证 |
| M9-T6 文档 | README 增加发布流程、Android 差异与未覆盖功能 | 文档审阅 | 许可证与第三方二进制许可清单仍需发布前补齐 |

## 发布命令

```sh
Tools/fetch-mpv.sh
VERSION=0.9.0 BUILD_NUMBER=1 Tools/package.sh
```

签名发布时增加 `SIGNING_IDENTITY` 和 `NOTARY_PROFILE`。脚本默认不上传、不推送任何 Git 内容。
