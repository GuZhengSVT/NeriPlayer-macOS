## 测试基础设施问题（既有，非本里程碑引入）

`PlaybackStateStore` 的引擎事件折叠依赖非结构化 `Task`，在**整机 CPU 竞争下**会被长时间
饿死，表现为一批 store/UI 用例等快照超时（8~20s）。复现方式与结论：

- 单跑：`swift test` 稳定 339/339，约 12s；
- 加压：另起 8 个 CPU 自旋进程后跑全量，约 3/5 轮出现 1~2 个超时用例
  （`PlaybackEntryUITests`、`PlaybackStateStoreTests`、`PlayerEngineTests` 均命中过）；
- 失败现场：store 当前快照与订阅者最后收到的快照**完全一致**且都停在旧值，
  说明不是「测试等错东西」，而是折叠任务没被调度；
- 已排除：任务优先级（改为 `.userInitiated` 后仍复现）、真实音频输出（静音后仍复现）。

本次已消除该类问题中属于**测试自身**的部分（有损流 `bufferingNewest(1)` 上做「某条历史
文案必须出现过」的断言、`contains` 匹配重复文案、重载用例用「非空闲」当完成信号）。
剩余部分属于产品侧调度问题，建议另开任务处理，可选方向：把状态折叠从非结构化 `Task`
改为引擎事件线程上的同步回调（`PlayerEngine` 暴露 `onStateChange`），从根上移除对
协作线程池调度的依赖。
