# NeriPlayer macOS 体验补齐与修复方案

> 日期：2026-10-01（Asia/Shanghai）
> 状态：**待用户审查，尚未开工**。本文是修改方案，不是完成报告。
> 本轮范围：亲自操作现有应用、读取 macOS / Android 源码、编写本文；没有修改应用代码、重新打包或执行云端写入。

## 1. 审查结论与建议范围

当前 macOS 版已经有播放、数据库、在线客户端、下载、歌词、同步等基础，但用户界面与这些基础能力之间还存在明显断层。建议保留 SwiftUI + libmpv + GRDB 的现有工程，按下面的顺序补齐：

1. **P0：恢复基本可用性。** 解决歌单重复加载、封面不可见、首页依赖探索状态、底部控制栏不出现，以及设置中的无效按钮。
2. **P1：形成完整音乐播放器。** 增加独立播放页面、真正的播放队列、音质选择与实际规格显示；补齐首页内容、主要设置、歌单与下载操作、历史和统计入口。
3. **P2：进一步对齐 Android。** 更多歌词来源和编辑、创作者详情、评论、B 站分段跳过、更多视觉偏好等，按本文单独审查范围。

Android 是功能与行为参考。macOS 应采用桌面布局、鼠标、键盘、菜单栏和系统音频设备交互，不需要复制手机的整套排版或 Android 专属服务、权限与 USB 驱动。

**建议本次批准 A、B 两阶段（第 10 节），C 阶段逐项决定。** P2 的差异也已列入本文，避免把未覆盖的功能误认为已经移植。所有表中的“补充”“修复”“验收”都指后续工作。

## 5. 页面与导航方案

### 5.1 主窗口与底部音乐控制器

保留五个主导航：首页、探索、媒体库、下载、设置。底部播放器固定在主窗口内容下方，切页不会重建播放会话。

| 区域 | 需要提供的内容与交互 |
|---|---|
| 左侧曲目信息 | 真实封面、歌名、歌手、收藏状态；点击封面 / 标题进入独立播放页；支持长标题截断与完整 tooltip |
| 中央控制 | 上一首、播放暂停、下一首；播放模式切换；加载 / 缓冲可见，不用“暂停”冒充失败 |
| 进度 | 当前时间、可拖动 / 点击的进度滑杆、总时长；拖动时预览，结束后执行 seek；未知时长明确禁用 |
| 右侧工具 | 音量 / 静音、实际音质及切换菜单、队列、歌词；空间不足时次要工具折叠到更多菜单 |
| 状态 | 实际音源、缓存 / 离线、失败重试；首次换源给一次反馈，持续信息融入播放器 |
| 空队列 | 默认保留紧凑的“未播放”状态，播放按钮禁用；可审查是否改为空队列隐藏 |

播放器以同一应用级状态供主窗口、播放页、菜单栏、媒体键使用。排查当前缺失时优先修正状态注入与订阅，不再用首页临时状态或读取另一页来唤醒控制栏。

### 5.2 独立歌曲播放页面

新增“正在播放”页面，可由底部播放器、首页当前曲目、播放菜单进入。默认在主窗口内容区展开，保留返回能力和原页面位置；不阻塞浏览。独立窗口作为后续桌面增强，首轮不要求同时维护两套播放 UI。

### 5.3 真正的播放队列

- 批量选择与批量移除在 P1 后半段实现。
- 移除当前项、清空、重复曲目、随机排序与重启恢复有明确行为；保存歌单与队列分开。

Core 已有部分队列操作，但缺少 UI 所需的完整命令转发和排序流程，需贯通到 `PlaybackStateStore`，不能直接绕过播放会话修改内部数组。重复曲目可作为独立队列条目存在；再次点击同一歌曲播放默认定位已有条目，不无限追加。

## 6. 缓存与封面修改要求

### 6.1 分清三类数据

| 类型 | 现状 | 需要实现的行为 |
|---|---|---|
| 平台页面数据 | 单份数组 + `loadedSources`，无详情持久缓存 | 内存快照 + GRDB 持久缓存，歌单元数据、曲目顺序、区块、分页、更新时间分别保存 |
| 封面图片 | 主要由 `AsyncImage` 临时请求；无统一磁盘缓存 / 错误状态 | 统一图片加载器，内存与磁盘缓存、相同请求合并、缩略图尺寸、失败重试和真正缺图状态 |
| 播放音频 | 已有 Range 分块、完整覆盖后发布和完整性校验 | 保留现有机制；补音质 / 编码维度、容量上限、最近使用淘汰和正在使用保护 |

不要把“缓存完整音频”当成“已经缓存歌单”。播放 URL 有时效，仍在播放 / 下载前解析或刷新，不能长期作为歌曲身份保存。

### 6.2 页面缓存契约

1. 键至少包含平台、账号上下文、资源类型和资源 ID。公开资源可共用；私人歌单、推荐和雷达按账号隔离，凭据本身不写入缓存键或日志。
2. 同次运行再次打开详情、来回切平台，优先显示内存快照；应用重启后可先显示磁盘快照。
3. 手动刷新保留内容，后台更新成功后替换；失败保存旧快照并展示重试。
4. 同一资源重复请求合并；分页可追加，部分结果不能标为完整；只在对应账号 / 平台 / 请求代次仍有效时发布。
5. 登录、退出和账号变更使对应私人缓存失效；跨账号不显示旧账号歌单。旧账号缓存可清理，但不能删除用户自己创建的本地收藏。
6. 保存页面的筛选、排序、滚动锚点与选中项；返回详情不从顶部重新开始。
7. 请求失败不是成功空列表，不写成“有效空缓存”；成功返回空列表可以保存。

建议首轮默认值（属于方案选择，尚未实现）：我的歌单列表 / 详情 15 分钟，普通首页推荐 30 分钟，每日推荐按平台有效日期失效；雷达按账号上下文和刷新结果更新。过期缓存仍可展示并后台刷新，离线时显示缓存日期。手动刷新无视新鲜期，但合并同一在途请求。

GRDB 只增加必要的缓存记录与读取接口，复用现有在线模型；不为每个平台建立一套重复缓存框架。

### 6.3 封面排查和加载

必须分别确认：接口是否返回封面、映射是否保留、URL 是否可加载、渲染是否成功、缓存是否复用。

- 网易云：核对歌单 `coverImgUrl` 与其他响应中的 `picUrl / coverUrl`，歌曲 `al / album` 和备用字段；可支持的 CDN URL 统一 HTTPS。当前解析只覆盖部分字段，HTTP 地址也直接传给 UI，因此字段差异与传输限制都是需要检查的候选原因。
- Bilibili：收藏夹接口缺图时优先读收藏夹元数据；必要时取首个有效视频封面。不要拉取全部收藏资源来补一张封面。
- YTM：核对不同 renderer 的 thumbnail 层级，处理有效 CDN 地址，选适合尺寸的图片；登录后确认收藏页、详情页、首页一致。
- 回退顺序：资源显式封面 → 同资源缓存封面 → 第一首有效曲目封面 → 占位。仅因 URL 非空不能认定可用；URL / 加载失败可触发一次合理回退。
- 图片补全与列表加载分开；可见项优先，取消离屏任务；缓存或请求完成后不改变网格尺寸和滚动位置。
- 图片失败诊断记录状态码、错误类型和平台即可；不输出 Cookie、签名查询串或完整账号资料。

实现后须对实际的网易云账号复验 U03–U05；B 站和 YTM 需使用已授权账号单独验收。**当前不能声称 YouTube 封面已经正常。**

## 7. 音质选择、显示与音频控制

### 7.1 三平台音质

以 Android 的默认偏好为参考：网易云 `exhigh`，Bilibili `high`，YTM `high`。默认偏好是请求目标，播放器显示的是实际拿到的流。

| 平台 | 参考档位键 | macOS 行为 |
|---|---|---|
| 网易云 | `standard`、`higher`、`exhigh`、`lossless`、`hires`、`jyeffect`、`sky`、`jymaster` | 根据账号权限和歌曲实际资源提供可用档位；返回降级时显示实际档位及原因，不能显示虚假的无损 |
| Bilibili | `low`、`medium`、`high`、`lossless`、`hires`、`dolby` | 解析普通 DASH、FLAC、Dolby 等候选；按偏好和可用格式选择，适配实际返回值 |
| YouTube Music | `low`、`medium`、`high`、`very_high` | 按实际可用流、码率与编码映射；这些是客户端选择档位，不承诺所有账号都有最高档位 |
| 本地文件 / 下载 | 不提供远端升档 | 显示实际编码、采样率、位深、声道和码率（可获得时），可定位文件 |

档位键来自 Android 参考实现，**不代表本轮已经验证各平台当前接口都支持它们**。实现时先以响应和账号权限决定可选择项；不可用项可禁用并解释原因，不绕过会员或 DRM。

### 7.2 端到端信息流

新增统一的实际音频信息：请求档位、实际档位、可选档位、歌曲原平台、实际流平台、codec / MIME、码率、采样率、位深、声道、缓存命中。贯通解析器 → 播放会话 → 播放快照 → 底部栏 / 播放页 / 系统展示需要的字段。

- 音质切换重新解析并加载对应流，保持当前时间与播放 / 暂停意图；加载失败恢复原流和原状态，给出错误。
- 自动换源后按目标平台偏好选择，显示目标流的规格，不能继续挂网易云高音质标签。
- 缓存包含实际档位与编码；需要更高档位时低档缓存不满足请求。旧缓存没有这些信息时标为未知，不伪造。
- 下载音质可跟随播放默认值或独立设置；任务和下载文件保存实际音质信息。
- 采样率显示分清音源规格和设备输出规格；系统重采样后不能把输出采样率当成文件采样率。

### 7.3 播放控制

复用已有 EQ、响度、淡入淡出，并补输出设备选择、倍速、音高、声道平衡、响度归一化、睡眠计时与“播放完当前曲再停止”。CoreAudio 设备变化和蓝牙断开有可设置的恢复策略。

现有“顺次交叉淡变”不是真正两首重叠 crossfade。首轮按实际行为更名并解释；真正重叠播放作为独立后续任务，需评估 libmpv 会话与音效链，不能通过改文案宣布已支持。独占输出需真 DAC 验收，macOS 不照搬 Android USB UAC / DSD 驱动。

### 9.2 原生适配或明确不照搬

- Android Service / WorkManager → macOS 应用生命周期、任务调度和关闭窗口策略。
- Media3 / 通知栏 → libmpv、系统 Now Playing、媒体键、菜单栏播放器。
- Android WebView 登录容器 → 平台允许的二维码 / Cookie / 浏览器授权方式，不为外观一致强行嵌 WebView。
- Android USB 独占、UAC、DSD → CoreAudio 输出设备与独占能力，真设备验证后再承诺更高级输出。
- Widget、通知渠道、安卓悬浮窗权限、震动 → 菜单栏、桌面歌词、macOS 通知与输入习惯。
- Android 状态栏 / 蓝牙歌词 / 灵动岛 → 单独评估 macOS 是否有合适承载，首轮不做名称相同但没有效果的设置。
- 手机触控手势 / DPI / 移动网络 → 键盘、鼠标、窗口密度和 macOS 受限网络策略。

### 11.3 测试规模

按变更风险添加缓存 / 请求隔离、音质策略 / 质量缓存、队列与进度恢复等必要回归测试；保留现有播放、下载、歌词与数据库测试。UI 外观、账号与音频设备由真实应用操作验收。

遵守仓库既有构建检查：`swift build`、`swift test`，相关 lint / 打包检查按影响执行；不存在“文档写完等于这些检查已通过”的结论。每项验收记录 `PASS / FAIL / NOT_RUN`、应用构建标识和条件。
